# QA-02 — Bộ ca kiểm thử nghiệm thu

Tài liệu nghiệm thu thủ công cho đồ án Fashion Shop. Mỗi ca ghi rõ bước làm, kết quả mong đợi và cột kết quả thực tế để người chạy điền.

- Người phụ trách: Trịnh Tấn Phát.
- Nguồn bổ sung: 8 ca của Võ Thị Ngọc Như tại [QA-02-Ngoc-Nhu.md](QA-02-Ngoc-Nhu.md) (đã chạy, ghi kết quả).
- Phạm vi: ứng dụng desktop (WinForms), website, cơ sở dữ liệu và tích hợp giữa hai ứng dụng.

## 1. Chuẩn bị môi trường

1. Bật cơ sở dữ liệu: `docker compose up -d`, chờ `docker compose ps` báo healthy.
2. Dựng lại dữ liệu sạch (khuyến nghị dùng bản sao, không chạy trên dữ liệu thật):
   `sqlcmd -S localhost,1433 -U sa -P <mật khẩu trong .env> -f 65001 -i CSDL_ShopQuanAo.sql`
3. Chạy web: `run-web.cmd` → mở `http://localhost:5193`.
4. Chạy desktop: `run-desktop.cmd` hoặc `dotnet run --project QuanLyDesktop`.
5. Tài khoản mẫu: `admin` / `123456` (Quản trị), `nhanvien` / `123456` (Nhân viên).

## 2. Quy ước ghi kết quả

- Cột **Kết quả thực tế**: ghi `Đạt` hoặc `Không đạt` kèm một dòng mô tả và bằng chứng (ảnh chụp, mã đơn, câu SQL đã kiểm tra).
- Ca **Không đạt** phải ghi rõ chênh lệch so với mong đợi để mở việc sửa.
- Không đánh dấu Đạt khi chưa thực hiện đủ các bước.

## 3. Nhóm A — Đăng nhập và phân quyền

| Mã | Các bước | Kết quả mong đợi | Kết quả thực tế |
|---|---|---|---|
| A-01 | Đăng nhập `admin` / `123456` | Vào màn hình **TỔNG QUAN CỬA HÀNG**, hiện tên và quyền Admin, đủ các mục menu | |
| A-02 | Đăng nhập `admin` / `sai-mat-khau` | Báo **Tên đăng nhập hoặc mật khẩu không chính xác**, ô mật khẩu được xóa và giữ tiêu điểm, không vào được hệ thống | |
| A-03 | Chạy `UPDATE Users SET IsActive = 0 WHERE Username = 'nhanvien'`, sau đó đăng nhập `nhanvien` / `123456`, cuối ca khôi phục `IsActive = 1` | Không đăng nhập được, thông báo giống ca sai mật khẩu (không tiết lộ tài khoản bị khóa) | |
| A-04 | Đăng nhập `nhanvien` / `123456` rồi mở **Quản lý danh mục** | Báo **Không đủ quyền**; các màn hình còn lại vẫn dùng được theo phân quyền | |

## 4. Nhóm B — Sản phẩm (desktop)

| Mã | Các bước | Kết quả mong đợi | Kết quả thực tế |
|---|---|---|---|
| B-01 | **Quản lý sản phẩm** → nhập mã, tên, giá bán, chọn danh mục → **Thêm Mới** | Sản phẩm xuất hiện trong lưới; `SELECT * FROM Products WHERE ProductCode = '<mã>'` có bản ghi `IsActive = 1` | |
| B-02 | Bỏ trống mã hoặc tên hoặc giá bán rồi bấm **Thêm Mới** | Chặn lưu và hiện cảnh báo, không tạo bản ghi rác | |
| B-03 | Nhập giá bán âm hoặc chữ vào ô giá | Chặn lưu, thông báo giá không hợp lệ | |
| B-04 | Sửa sản phẩm: nhập **URL ảnh**, **Giá gốc** lớn hơn giá bán, tick **Sản phẩm nổi bật** → **Cập Nhật** | Lưu đúng 3 trường; web hiện ảnh, giá gốc gạch ngang và nhãn giảm giá | |
| B-05 | Chọn sản phẩm → **Ngừng bán** | Sản phẩm ẩn khỏi web và danh sách đang bán; trong CSDL chỉ đổi `IsActive = 0`, không mất dòng dữ liệu | |

## 13. Ghi chú khi chạy

- Các ca làm thay đổi dữ liệu (E-02, F-04, G-02, J-04) nên chạy trên bản sao cơ sở dữ liệu hoặc ghi lại mã đơn, mã phiếu để hoàn tác.
- Ca A-03 cần khôi phục `IsActive = 1` cho `nhanvien` sau khi kiểm tra.
- Nếu một ca phụ thuộc tính năng chưa merge (ví dụ khối sản phẩm liên quan WEB-04, xuất CSV DES-06), ghi rõ "chưa có tính năng" thay vì đánh Không đạt.
